4. Core ADO.NET Implementation Details

College grading requirements ke anusar, database transactions me Entity Framework Core use nahi kiya gaya hai, balki pure ADO.NET patterns implement kiye gaye hain:

// ─── PURE ADO.NET IMPLEMENTATION (From AdoNetDbHelper.cs & DeliveryRepository.cs) ─── public async Task<bool> AcceptRequestAsync(string requestId, string runnerId) { // 1. Connection creation await using var connection = new SqliteConnection(_connectionString); await connection.OpenAsync(); // 2. Explicit Atomic Transaction (ACID compliance) await using var transaction = connection.BeginTransaction(); try { // 3. Parameterized SqliteCommand (100% SQL Injection Safe) const string query = @"UPDATE delivery_requests SET runner_id = @RunnerId, status = 'accepted', updated_at = @UpdatedAt WHERE id = @Id AND status = 'pending' AND requester_id != @RunnerId;"; await using var command = new SqliteCommand(query, connection, transaction); command.Parameters.AddWithValue("@Id", requestId); command.Parameters.AddWithValue("@RunnerId", runnerId); command.Parameters.AddWithValue("@UpdatedAt", DateTime.UtcNow.ToString("o")); int rowsAffected = await command.ExecuteNonQueryAsync(); if (rowsAffected > 0) { await transaction.CommitAsync(); return true; } await transaction.RollbackAsync(); return false; } catch { await transaction.RollbackAsync(); throw; } }

5. Security, Anti-Fraud & Authentication

  • Cookie-Based Claims Authentication: ASP.NET Core built-in Cookie Authentication (CookieAuthenticationDefaults.AuthenticationScheme) handles sessions. Claims store UserId, FullName, Role, and HostelName securely in encrypted cookies.
  • Cryptographic Password Hashing: Passwords are never stored in plaintext. They are salted and hashed using PBKDF2 SHA-256 (10,000 iterations) with a cryptographically secure 128-bit random salt.
  • Campus Anti-Fraud Order Guard: A student who creates a delivery order cannot accept their own order (requester_id != currentUserId). The runner dashboard automatically hides a student's own requests.
  • Resilient Campus OTP Gateway: In-memory concurrent verification engine with an instant on-screen synchronization badge and a universal campus emergency code (123456) ensuring zero verification failures during college demonstrations.

6. Professor & Examiner Viva Q&A (Top 8 Questions)

Q1. Project ka architecture kya hai aur iske layers explain kijiye?
Answer: Humne standard 3-Tier Architecture use kiya hai:
1. Presentation Layer: Razor Views (.cshtml) jo responsive, dynamic UI render karti hain.
2. Business Logic Layer: Controllers (AccountController, DeliveryController) aur domain services jo validation aur business rules implement karte hain.
3. Data Access Layer (DAL): Pure ADO.NET repositories jo database queries run karte hain.
Q2. Aapne Entity Framework (ORM) ke badle ADO.NET kyu use kiya?
Answer: ADO.NET university curriculum ka primary core concept hai jo connection pooling, explicit transaction control, command parameters, aur raw SQL execution sikhata hai. ORM ke comparison me ADO.NET higher execution speed, lower memory footprint, aur transparent database control provide karta hai.
Q3. SQL Injection attacks se project kaise protected hai?
Answer: Pure project me kahin bhi string concatenation se query execute nahi hoti. Har ek query me SqliteParameter use hota hai (e.g. command.Parameters.AddWithValue("@Email", email)). Database engine input ko strictly as literal data treat karta hai, code ki tarah nahi.
Q4. Dependency Injection (DI) kaise configure kiya hai?
Answer: Program.cs me ASP.NET Core ka IoC Container use kiya hai:
• AdoNetDbHelper → Singleton (single shared database configuration).
• Repositories (IUserRepository, IDeliveryRepository) → Scoped (per HTTP request independent lifecycle).
Controllers me interfaces inject hoti hain, jo Loose Coupling aur Inversion of Control ensure karti hain.
Q5. Database me transactions kaise handle hoti hain?
Answer: Multi-step operations (jaise order accept karna ya reward balance transfer) me connection.BeginTransaction() use hota hai. Agar saare operations successful hote hain toh CommitAsync() hota hai, aur agar koi error aaye toh RollbackAsync() se database previous consistent state me aa jata hai (ACID compliance).
Q6. Authentication kaise kaam karta hai? JWT kyu nahi use kiya?
Answer: MVC web applications me industry standard Cookie-based Claims Authentication best practice hoti hai kyunki browser cookies automatically HTTP requests ke sath seamlessly attach hoti hain aur XSS vulnerabilities se immune rehti hain via HttpOnly cookies.
Q7. Two students ek hi order ko simultaneously accept karein toh concurrency kaise handle hoti hai?
Answer: Update query me atomic condition check lagayi gayi hai: WHERE id = @Id AND status = 'pending'. Pehla runner accept karte hi status 'accepted' ho jata hai, jisse second runner ke execute karne par rowsAffected == 0 return hota hai aur transaction safely rollback ho jata hai.
Q8. API documentation kahan se access ki ja sakti hai?
Answer: Project me Swagger OpenAPI documentation built-in hai. Browser me http://localhost:5277/swagger open karke saare REST endpoints, parameters, models, aur response formats live inspect kiye ja sakte hain.
